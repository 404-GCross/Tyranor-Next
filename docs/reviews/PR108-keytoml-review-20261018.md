## 原因、修复与影响

旧 Siglus 接入依赖重编运行库及新增舞台几何 ABI。按提交者要求，当前路线使用上游原库、
原有 create/set_surface/resize 接口；创建成功后只读运行时生成的 key.toml 与实际选中的 Gameexe，
解密/解压配置取得 SCREEN_SIZE，再申请同尺寸 producer，之后执行共享滤镜链。
宿主不恢复密钥，不读取 EXE、CHS、Scene，也不写游戏目录。
配置缺失、密钥非法、扩展不支持或尺寸不可信时保持原呈现，不把屏幕分辨率冒充舞台分辨率。
原库没有运行时舞台查询，因此此处取得的是所选配置的逻辑尺寸，不宣称内部 renderer 几何回读。

## 二进制、来源与许可

- 当前所有预编译引擎库相对基线零差异；Siglus 原库 SHA-256：
  `fdef411e1f30550ef7adb7ab4ff1f383433aee94be7609a481eb18c13c3563df`。
- 当前提交序列不含旧 Siglus Rust 补丁、专属重编 workflow、重编脚本、几何 ABI 或替换库。
  项目正常构建仍编译宿主 JNI 桥，不能把桥接代码与引擎本体重编混为一谈。
- 格式参考固定 siglus_rs `5f358ef1360b0439e92aed2b749e8f25d8721954`。
  Java 读取器独立实现；256 字节固定 XOR 表独立文件保留 MPL-2.0 来源和完整许可，表值逐项核对一致。
- 原库及许可 SHA 继续受普通构建资源校验约束，没有关闭来源校验。
- Anime4K 扩展（MIT）和 GPUOpen CAS（MIT）各自单独提交，描述器、菜单值、颜色、资源和许可证随贡献独立加入。
  CuNNy2、用户导入及自研 Artemis 的滤镜接入不在本分支。

## 配置读取复核

对照固定上游 resource.rs、host.rs、gameexe.rs、key_toml.rs、lzss.rs 核对初始 append、
文件优先级、大小写匹配、明文/固定 mask/运行时 key 与 LZSS、最终 SCREEN_SIZE 定义。
key 数组优先于 key_hex；明文及固定 mask 不强制要求密钥，需游戏 key 的模式缺失时拒绝。
不支持的解码覆盖保守拒绝；不会因高优先级文件解码失败而偷换低优先级配置。
路径 canonical 边界、歧义拒绝、体积和像素上限、解压膨胀限制及取消检查均保留。
新增 23 项合成配置回归，没有私有游戏密钥或解密文本；审查时仅阅读，执行交由 CI。
已知保守拒绝边界：带 UTF-16 BOM 且恰好只有三条配置的最小 DAT 文本，首行可能不计入格式探测；
此时禁用可选滤镜，不产生错误尺寸。

## 线程、窗口与资源复核

- 所有使用 live handle 的 JNI 创建、步进、输入、IME、窗口及销毁进入单一 owner 线程。
  UI 不等待 BufferQueue；独立 GLES 消费线程解除背压，正常无绘制 step 可继续执行。
- Choreographer 至多一个待执行/正在执行 step；输入队列有界，普通饱和后保留 reset 槽，
  在 reset 完成前抑制新输入；消息框回复使用独立保留槽，不能被普通输入挤掉。
  此项为独立审查发现的 P2，已修复并复读。
- 持有自有 Surface 快照，窗口世代和连接请求拒绝迟到交接；不释放 SurfaceHolder 借用对象。
  原库实际 set_surface 反汇编确认返回 0/1，与 JNI boolean 一致；ANativeWindow 引用按连接生命周期保留。
- 关闭先停止准入，由同一 owner 销毁 native 后释放 producer；不从另一线程销毁运行中句柄。
  永久 native 阻塞时保留有界 owner/consumer，拒绝无上限重建；这不能保证故障驱动恢复。
- 首次 create 的原生密钥恢复没有任意十秒失败期限；普通调用忙碌提示仅安排有序恢复。
- Activity 销毁取消后台读取，请求和 owner 身份防止迟到结果挂接其它游戏。
